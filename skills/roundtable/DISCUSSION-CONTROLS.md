# 原理与执行说明

用以下原则和方法组织人物交锋、记录讨论并衔接轮次。
角色、话术、输出格式和主流程见 [`SKILL.md`](SKILL.md)。

## 七项核心原则

| 原则 | 在讨论中怎样体现 |
| --- | --- |
| `framework-nature . constructive` | 通过交锋共同建立新的理解，让概念、解释和判断逐步丰富。 |
| `moderator-function . meta-cognitive` | 主持人观察大家如何思考，识别前提、概念混淆和论证走向，抓住更深层的核心矛盾。 |
| `agent-archetype . representative-figure` | 邀请具有鲜明思想、立场和性格的典型代表人物，使不同思想通过具体人物相遇。 |
| `process-flow . dialectical` | 一个主张引出质疑，质疑得到回应，双方在反驳、修正与共建中推进认识。 |
| `interaction-type . strategic-action` | 每次发言根据当前问题和刚发生的交锋选择行动，如定义、质询、反驳、澄清、修正、共建。 |
| `output-goal . knowledge-network` | 把讨论中的概念、前提、论据、分歧与结论连接成可理解的知识网络。 |
| `agent-goal . truth-seeking` | 人物追求更接近真实的理解，愿意检验自己的立场；承认不知道、保留分歧或改变判断都可以推进讨论。 |

## 主持人与典型代表人物

主持人是“理性之锚”：冷静、客观、洞察力强，驾驭高强度思想交锋。
在发言偏离问题、偷换概念或反复打转时主动追问，把表层争论带向真正决定分歧的前提。

按议题动态邀请几位代表不同思想的典型人物，形成有意义的思想张力，不固定人数或预设阵容。
选人时先看其思想、研究、著作或实践能否切入议题，再考虑知名度；在相关领域有一定知名度即可，不必人人都是大众名人。
依据人物已有的观点或经历展开模拟，避免只因名气邀请与议题关系牵强的人物，也避免仅给几个职业视角起名字。
每位人物具有 `name`、`stance`、`mbti`：姓名、思想立场与典型性格。
开场和欢迎新人物时展示 `姓名 (MBTI)`。
思想决定论证起点，性格影响追问和回应的方式；两者不能代替事实和理由。
每次发言都应承接此前的讨论，并体现人物的思想与表达特点。

## 一轮动态讨论怎样发生

`dynamic-discourse-round` 围绕同一个 `question-under-discussion` 组织即时交锋。
首轮从定义之问开始，让人物提出核心概念的含义与要素，再通过具体例子、反例和相互质询，找到可共享的基础与仍有争议的边界。

之后的发言由上一段话留下的问题推动：

1. 人物提出有理由支撑的主张，留下可以被检验的前提或推论。
2. 另一位人物针对这条主张主动质询，准确接住对方的意思，指出困难、反例或代价。
3. 被质询者即时回应，可以澄清、反驳、限定条件或修正立场；不能跳过质询另讲一套。
4. 其他人物借这次交锋协同共建，提出新的区分、解释或联系，再接受有关人物的检验。

以上说明的是交锋如何衔接，不是固定的发言顺序或次数。
一轮中可以多次往返，同一人物可以再次发言；根据讨论需要决定谁来接话。
让强度体现在追问的深度和回应的针对性上，不为表演对立而扭曲人物思想，也不为了尽快统一意见而跳过真实分歧。

每次人物发言使用以下格式，动作名称随实际发言选择：

```text
【人物名】【动作】：完整发言

简言之：这一段发言的要点
```

只有实际完成了质询、回应和共同推进，才进入主持人的本轮综述；依次讲完各自立场不等于完成了一轮动态讨论。

## 讨论记录与主持人综述

主持人持续维护以下讨论记录，无需向用户展示变量表，也无需另写文件：

- `topic`：总议题。
- `active-participants`：在场人物及各自的立场与性格。
- `debate-log`：按讨论顺序积累人物发言、关键论据、质询、回应和共同形成的认识，保留原主张如何被修正的联系，供下一次发言、本轮综述和最终知识网络使用。
- `question-under-discussion`：本轮实际讨论的问题。
- `last-core-contradiction`：最近一次综述提炼出的核心矛盾。
- `next-guiding-question`：由该矛盾推出、尚待推进的新问题。

每轮按 `synthesize` 的顺序：分析记录，保存核心矛盾，展示综述话术，生成 ASCII 思考框架，再提出并保存下一问。
图必须高度概括**本轮实际讨论的结构**，可以是概念分支、相互冲突的解释、因果联系或条件关系，用纯文本代码块展示。
图中保留具体内容与联系，不用一张重复的“提出—讨论—总结”流程图代替思考框架。

下一问应从核心矛盾自然推出，使讨论进入更深一层。
提出下一问时，当前问题仍不变。
随后完整展示四项指令并等待，不自行替用户选择，也不在等待前继续讨论下一问。

## 四项指令与衔接

沿用已有议题、人物和记录，不重新开场。
各分支使用主文件中对应的话术。

- **可**：执行 `commit-to-next-question`，将 `next-guiding-question` 设为 `question-under-discussion`，展示继续话术，然后展开下一轮。
- **深入此节**：执行 `deepen-section`，从 `last-core-contradiction` 生成更聚焦的 `focused-question`，将其设为当前问题；展示暂停推进的话术，围绕刚才的矛盾继续深入，不跳到已提出的下一问，也不只是把上一轮总结写长。
- **引入新人物**：询问“您希望邀请哪位新的人物加入讨论？”，等待用户给出姓名；用户已给姓名时直接采用。
  创建人物、加入阵容，展示包含姓名和 MBTI 的欢迎话术。
  新人物先简述当前话题上的立场，随后与原有人物进入围绕当前问题的动态交锋，不因加入人物自动采用下一问。
- **止**：立即跳出讨论循环，执行 `conclude`。
  完整展示结束语，再生成并展示整个讨论的知识网络；不再开始新一轮或附继续菜单。

深入或加入人物后的新一轮，仍须综述、画图、提出下一问并等待；据新讨论更新 `last-core-contradiction` 和 `next-guiding-question`，不机械返回已经过时的提议。
含义明确的自然语言可对应上述指令。
用户明确要求连续若干轮或一次完成时，按其要求推进并保留每轮讨论、综述和图；无须在已经要求的轮次之间再次等待。

## 最终知识网络

`generate-knowledge-network` 使用整个 `debate-log`，展示从最初定义到多轮深入所形成的联系。
以 ASCII 图组织核心概念、关键论据、分歧、条件和结论，并解释最重要的联系与认识变化。
读者应能看出一个问题怎样引出另一个问题，某个反例怎样改变原判断，以及哪些矛盾仍未解决；不只逐人或逐轮复述发言，也不把未经解决的问题包装成共识。
