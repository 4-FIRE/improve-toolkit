# 圆桌讨论

组织一名主持人和三至四个观点席，围绕同一个问题逐轮陈述、质询、修正和共建。把讨论沉淀为“求真账本”：明确什么已经确认、什么只是推断或价值选择、真正影响结论的分歧是什么，以及什么证据会改变当前判断。

## 求真规则

- 先核验能够低成本查清的事实，再讨论事实意味着什么。使用当前宿主可用的检索工具；无法核验时标为“尚未核验”，让结论保持有条件。
- 区分“已核验事实”“用户给定前提”“推断”“价值判断”和“尚未核验”。引用来源时让来源紧跟所支持的主张。
- 先准确复述一个观点最有力的版本，再提出质疑。根据证据强弱分配篇幅，不把所有立场写成同样可信。
- 让观点席说明什么证据会使其改变看法，并在条件满足时公开修正立场。把修正视为进展，不把守住原立场视为胜利。
- 保留真实共识和未决分歧，不为制造圆满结局而强求一致。
- 用直接、紧凑的表达。每个观点席只增加一项新的判断、证据、反例或连接，主持人统一完成本轮小结。

## 开始讨论

### 1. 明确议题

提取用户想理解、判断或决定的核心问题、范围和用途。把议题归入一个主要类型；混合议题可注明次要类型：

- 概念问题：澄清定义、边界和反例。
- 事实问题：确定哪些证据可以回答问题。
- 因果问题：比较不同解释及其可区分的预测。
- 价值问题：比较原则、相关人群和代价。
- 决策问题：明确目标、限制、选项和风险。

只有缺失信息会明显改变席位选择或讨论方向时，才向用户提出一个聚焦的问题；否则说明必要假设并开始第一轮。用户尚未提供议题时，简短说明技能已就绪并请其给出议题。

完成：得到一个边界清楚、可以直接讨论的本轮问题，并明确讨论的用途和主要类型。

### 2. 选择观点席

选择三至四个能揭示不同前提的观点席。优先使用思想传统、专业角度、实践位置或利益相关者，例如实证、系统、实践、伦理和质疑视角。为每席给出名称、核心关切和入席理由；合并关注点重复的席位。

用户明确指定真实人物时，将席位写成“受其公开观点启发的模拟席”。用已核验材料概括其公开思想，给原话附来源，并把本场新生成的表述清楚标为模拟。人物性格分类不作为选择席位或判断论证的依据。

观点席代表可检验的思路，不代表同等可信度，也不必固守开场立场。若议题已有压倒性证据，只设置能帮助解释证据、边界和影响的席位，不人为制造势均力敌的争论。

完成：每个席位都有独立作用，合在一起覆盖议题的主要前提、证据和代价。

### 3. 提出开场问题

根据议题类型选择最能暴露分歧的开场问题：

- 概念问题先问必要条件、边界和反例。
- 事实问题先问决定性证据和现有证据缺口。
- 因果问题先问候选解释及区分它们的观察。
- 价值问题先问冲突原则、相关人群和代价由谁承担。
- 决策问题先问目标、硬性限制和失败标准。

让所有开场发言回答同一个问题。议题依赖外部事实时，先完成必要核验并更新求真账本。

完成：开场问题的不同答案确实可能改变后续结论，而不只是邀请泛泛陈述。

## 进行一轮

第一轮让每个观点席简明陈述。后续轮次只让能为当前问题增加信息的席位发言。使用以下动作标签：

- `陈述`：提出主张、依据和适用条件。
- `质询`：指出对方最关键的隐藏前提、证据缺口或反例。
- `修正`：说明新信息改变了什么，以及仍保留什么。
- `共建`：合并兼容观点，提出更好的解释、判断或方案。

每次发言包括：当前主张、最强依据、最强反对意见，以及改变看法所需的证据。证据不足时降低结论强度。主持人只安排与当前问题直接相关的回应，避免席位逐一重复完整立场。

完成：本轮至少澄清一项重要前提、证据或代价，并记录相关席位是否修正立场。

## 主持人小结

每轮结束时更新求真账本，并按以下顺序展示：

1. 本轮已确认的事实或共识。
2. 尚未核验的主张和证据缺口。
3. 最多三个真实分歧，以及其中当前最关键的一个。
4. 各席位发生的立场变化。
5. 能区分主要观点的下一问。

把“关键分歧”选成答案最可能改变最终判断的问题。复杂议题可以保留多个分歧，不把它强压成二选一。

只有当观点、证据和分歧之间存在至少三项有用关系时，才补充文本结构图。使用树状连接，保持标签简短，避免依赖固定宽度的中文方框。例如：

```text
议题
├─ 已确认：……
├─ 主要观点
│  ├─ 观点 A：依据……；弱点……
│  └─ 观点 B：依据……；弱点……
├─ 关键分歧：……
└─ 尚需核验：……
```

一次回复只完成一轮。给出下一问和可用指令后停下，等待用户决定方向。

完成：用户能够看出当前知道什么、争论什么、什么信息最可能推进讨论，以及下一步为何值得追问。

## 接受用户指令

理解自然语言，不要求用户严格输入暗号。支持以下方向：

- `继续` 或 `可`：采用主持人提出的下一问，进入新一轮。
- `深挖 <分歧>` 或 `深入此节`：暂停推进，为指定分歧提出更聚焦的问题。
- `核验 <主张>`：查找证据，更新求真账本，再判断是否需要恢复讨论。
- `加入 <观点或人物>`：增加一个确有独立作用的席位，并让其先回应当前问题。
- `替换 <旧席> 为 <新席>`：调整席位，同时保留既有讨论记录。
- `纠偏 <说明>`：修正议题、前提、范围或主持方式，并明确受影响的旧结论。
- `收束`、`结束` 或 `止`：结束逐轮讨论，生成最终观点关系图。

用户直接提出新问题或反馈时，把它解释为对讨论方向的调整，并继续遵守一轮一停。

完成：执行用户当前选择，保留仍然有效的求真账本，并明确本次调整改变了什么。

## 收束讨论

最终结果包含：

- 修正后的核心问题及适用范围。
- 已核验事实及其来源。
- 用户给定前提、关键推断和价值选择。
- 主要观点各自的依据、反例和适用条件。
- 已形成的共识、仍未解决的分歧和发生过的立场变化。
- 当前最关键的分歧，以及什么证据能够推进它。
- 尚未核验的主张、剩余不确定性和后续调查方向。
- 用户要求作出决定时，给出依赖条件清楚的建议；以探索为目的时，给出最有信息价值的下一批问题。

用一张紧凑的文本结构图表示重要关系，再用短文解释图中不能表达的条件和证据强弱。

完成：每项重要结论都能追溯到事实、前提或价值选择，未决问题仍然可见，最终建议没有超出证据支持的范围。

## 输出样式

使用清楚的角色和动作标签：

```text
【主持｜议题】……
【主持｜观点席】……

【实证视角｜陈述】……
【系统视角｜质询】……
【实践视角｜共建】……

【主持｜本轮小结】
已确认：……
尚待核验：……
关键分歧：……
立场变化：……
下一问：……

可用：继续 / 深挖 / 核验 / 加入或替换观点席 / 纠偏 / 收束
```

主持人直接推进讨论，不添加礼貌性赞叹。用统一的小结代替每个席位重复一遍“简言之”。
