# 复盘与进化

复盘有两个分支：稳定事实进入记忆，可复用流程进入技能候选。会话上下文中的持久性门槛决定事实是否值得跨会话保留；`memory` 工具 schema 是保存触发、条目格式、target 和 action 的唯一事实源。

## 执行记忆整理

1. **盘点。** 扫描用户信号、稳定项目事实和调试根因；以当前任务或候选事实调用 `memory_recall`，把每个候选与全部相关旧条目配对。流程中只提取稳定根因或约束作为事实；当前源码、文档和用户明确纠正优先于召回结果。完成标准：每个候选都有来源，并已找到相关条目的 `entry_id` 与 `revision`，或确认没有匹配。
2. **分类。** 对每个候选应用会话持久性门槛和 `memory` schema，将其唯一分类为 `add`、`replace`、`remove`、`no-op` 或 `reject`。完成标准：每个候选恰有一个分类，且每个 mutation 都有明确 target、内容；替换和删除还有 `entry_id` 与 `expected_revision`。
3. **变更。** 只为 `add`、`replace`、`remove` 调用 `memory`；schema 提供 `project_dir` 时传入当前工作区根目录的绝对路径。发生 `REVISION_CONFLICT` 时重新召回并重新分类，不覆盖并发更新。容量不足时先合并重复项、替换失准条目并移除已失效事实，再腾退低价值、久未验证的项目事实，优先保留用户纠正和偏好。完成标准：每个计划 mutation 都有已核对的工具结果，所有已知冲突和重复均已解决。
4. **检查技能分支。** 当用户要求创建、修改、移动或删除技能、接受技能提案，或任务结束时出现可能复用的多步流程或关键坑点，加载 [`SKILL-CANDIDATES.md`](SKILL-CANDIDATES.md)，按其中状态推进到关闭、提案或实施。完成标准：技能分支已有唯一状态；该分支未触发时本步直接完成。
5. **报告。** 简短说明实际记忆变更和技能分支结果；没有 mutation 时明确说明没有需要长期沉淀的内容。完成标准：报告与工具结果及技能分支状态一致。
