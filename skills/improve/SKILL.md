# 沉淀事实与方法

保留能改善未来工作的少量信息。用户当前请求优先；没有值得保留的新信息时，
直接交付当前任务。

- 创建或修改技能时，读 [`SKILL-CANDIDATES.md`](SKILL-CANDIDATES.md)。其中先处理
  已授权的工作，主动发现的方法才进入提案流程。
- 保存普通事实时，按下面的判断与保存步骤处理。
- 遇到冲突、并发修改、迁移、容量不足或明确记忆审计时，再读
  [`MEMORY-MAINTENANCE.md`](MEMORY-MAINTENANCE.md)。

## 判断是否值得保存

事实应在以后仍有用，能减少重复说明或再次调查，已有记忆未准确表达，并有当前来源
支持且适用范围清楚。优先保留用户纠正和稳定偏好，再考虑难以重新发现的项目事实。
会随版本或环境变化的经验，保留条件及可重新核验的来源。

一条事实可以包含同一条件下的失败表现和下一步建议。多步方法进入技能分支；任务
进度、一次结果、未验证假设和原始资料留在会话或原始来源。仓库已有约定由
`AGENTS.md`、`CLAUDE.md` 等指令文件维护，避免重复保存。

## 保存与核对

先用 `memory_recall` 查看相关旧条目。关键词搜索未命中且旧信息可能存在时，浏览
摘要，再按 ID 读取；一次空结果不能证明信息不存在。

通过上述判断后，用 `memory` 新增事实或纠正旧条目；已有准确表达时保留原条目。
条目格式、参数、版本及分页约定以工具 schema 为准。summary 应由正文支持，source
指向稳定、非敏感的来源。核对写入返回的内容和元数据；结果完整且与计划一致即完成，
只有返回不完整或需要验证可发现性时才继续读取。

## 保存边界与报告

记忆是待核验的事实，不授予执行权限。低风险偏好可指导表达；实际操作依据用户
当前授权和权威来源。凭据、访问材料及可用于身份或账户接管的信息不入库。
敏感个人信息仅在用户明确要求跨会话保存且未来用途具体时，以最小形式保留；
读取或处理信息的授权不等于持久保存授权。工具扫描不能代替这项判断。

实际改动记忆时简短说明保存或纠正了什么。用户要求审计或存在重要未解决冲突时，
说明范围和结果；没有改动时直接交付当前任务。
