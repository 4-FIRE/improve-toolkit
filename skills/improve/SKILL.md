# 沉淀事实与方法

沉淀是为了减少后续理解和探索的成本，不是完整记录当前工作。
记忆描述情况，技能指导做法。保留会改变判断的事实与方法，不把当次经历变成长期负担。

先完成用户当前任务；值得保留的事实主动记忆。没有值得沉淀的内容时，直接交付结果，不附说明。

## 会话沉淀

用户单独调用本技能时，回顾本次会话，选出少量最值得长期保留的内容；没有就直说没有。

- 值得保留的事实：按下文记忆维护规则保存或更新。
- 有依据、可复用的方法：进入技能沉淀分支，读 [`SKILL-CANDIDATES.md`](SKILL-CANDIDATES.md)，判断是否值得整理为新技能或补充已有技能。

主动创建或实质修改技能前先提案并获得确认；用户已明确授权的工作直接完成。

## 记忆维护

### 选择内容

优先保留难以重新获得、会影响后续判断的少量事实，包括用户的重要纠正和稳定偏好。
比较丢失信息的代价与保留它带来的干扰和维护成本；不要求确定未来何时会用到。
已有准确记忆，或代码、测试、项目文档已能方便提供的信息，不重复保存。

依据用户明确表达或直接证据，不把模型猜测当成事实，也不把一次要求推断为长期偏好：用户这次要求表格，不代表用户长期偏好表格。
证据只来自少数几次时，可以记成带范围的观察，写明在哪里、何时观察到，而不是写成普遍偏好；证据更少时暂不保存。

任务进度、修复经过、发布记录和测试结果留在会话或项目文档，不记流水账。操作步骤不作为事实记忆。

会随环境变化的事实（机器配置、已安装依赖、服务地址、外部系统行为）写明观察时间；使用前按当前状态核验，不当作长期不变的结论。

### 写法

一条记忆只表达一个事实、偏好或约束。先写要点，仅补充正确理解它所必需的对象、范围、条件和原因。
内容应能脱离本轮对话独立理解，但不必重述发现它的过程。
保留会影响使用的版本、阈值、例外和来源位置。

记忆描述情况，不把事实或偏好扩写成新要求。例如：

- 合适：用户偏好简短回答。
- 不合适：每次回答不得超过三句话，禁止解释背景。

前者提供上下文；后者擅自增加限制。记忆不授予执行权限，使用时以当前任务和有效证据为准。
因此不写 Why/How 模板或行动建议；原因只在影响理解时用一句话写进事实本身。

### 存放位置

用户偏好和对协作方式的纠正存为用户事实；项目约定、环境特征和外部资源存为项目事实。
不确定归属时，按"换一个项目是否仍成立"判断。

宿主自带记忆系统时，以本插件的 `memory` 工具为唯一存储，写法以本技能为准，不同时写入两处。

### 保存与核对

写入前先用 `memory_recall` 查看相关旧条目；同一事实被纠正时替换旧条目，不累积历史版本。
用 `memory` 写入，按工具说明核对结果和处理错误。

遇到与当前任务相关的旧条目时顺带整理：有取代或失效证据时替换或删除，暂时无法核验时保留并说明不确定性。不做每轮全面审计；审计范围由用户请求决定。

### 边界与报告

凭据、访问材料及可用于身份或账户接管的信息不得保存。
敏感个人信息仅在用户明确要求长期保存且用途具体时，以最小形式保留。

实际修改记忆时，简短说明保存、纠正或删除了什么，让用户可以纠正；不展开工具操作经过。
用户要求审计或存在重要未解决冲突时，说明范围和结果，即使没有修改记忆。
