# 沉淀事实与方法

沉淀是为了减少后续理解和探索的成本，不是完整记录当前工作。
记忆描述情况，技能指导做法。保留会改变判断的事实与方法，不把当次经历变成长期负担。

先完成用户当前任务。值得保留的事实主动记忆；有价值的方法先提案，获得用户授权后写入技能。
主动不等于每轮都要新增内容。没有值得沉淀的内容时，直接交付结果。

- 创建或修改技能时，读 [`SKILL-CANDIDATES.md`](SKILL-CANDIDATES.md)。
- 保存事实时，使用下面的判断和写法。

## 选择内容

优先保留难以重新获得、会影响后续判断的少量事实，包括用户的重要纠正和稳定偏好。
不要求确定未来何时会用到；比较丢失信息的代价与保留它带来的干扰和维护成本。
已有准确记忆，或代码、测试、项目文档已能方便提供的信息，不重复保存。

依据用户明确表达或直接证据，不把一次要求推断为长期偏好，不把模型猜测当成事实。
用户这次要求表格，不代表用户长期偏好表格。缺少依据时暂不保存。

任务进度、修复经过、发布记录和测试结果留在会话或项目文档，不要记流水账。
操作步骤不作为事实记忆；也不因步骤多就自动整理成技能。

## 写法

一条记忆只表达一个事实、偏好或约束。像标签一样一眼能认出要点，但不压缩成无法独立理解的关键词。
先写要点，仅补充正确理解它所必需的对象、范围、条件和原因。

记忆描述情况，不把事实或偏好扩写成新要求。例如：

- 合适：用户偏好简短回答。
- 不合适：每次回答不得超过三句话，禁止解释背景。

前者提供上下文；后者擅自增加限制。记忆不授予执行权限，使用时以当前任务和有效证据为准。

保留会影响使用的版本、阈值、例外和来源位置。内容应能脱离本轮对话独立理解，但不必重述发现它的过程。

用常用词、短句和一致的名称。删除讨论经过、重复解释和空泛的 Why/How 模板。
不要为了让记忆显得完整，补写行动建议或操作步骤。

已有文档能充分说明的内容不再复述；确需保存时，只保留必要要点及可核验、非敏感的资料位置。
简短不能改变含义。

## 保存与核对

先用 `memory_recall` 查看相关旧条目。
搜索未命中但旧条目可能存在时，浏览摘要，再按 ID 读取。
纠正同一事实时替换旧条目，避免累积多个历史版本。

用 `memory` 写入选定内容，按工具说明核对结果和处理错误。
只有需要验证后续能否找到时，才补充代表性查询；普通写入不要求额外检索。

## 整理已有记忆

遇到相关条目时整理，不每轮全面审计。维护当前认识，不保存认识变化的流水账。

- 只处理与当前任务有关的条目。有取代或失效证据时替换或删除；暂时无法核验时保留并说明不确定性。
- 拆分或迁移时，先写入并核对目标条目，再删除源条目。
- 容量不足时，先处理重复和已证实失效的内容，再考虑合并。仍不足时说明限制，不为腾出空间删除仍有效的事实。
- 审计范围由用户请求决定。列出条目不等于核验事实；说明未核验的内容和未解决冲突。

## 边界与报告

凭据、访问材料及可用于身份或账户接管的信息不得保存。
敏感个人信息仅在用户明确要求长期保存且用途具体时，以最小形式保留。

实际修改记忆时，简短说明保存、纠正或删除了什么，让用户可以纠正；不展开工具操作经过。
用户要求审计或存在重要未解决冲突时，说明范围和结果，即使没有修改记忆。
其他情况下，没有修改就直接交付当前任务，不附记忆维护报告。
