# 沉淀事实与方法

先完成用户当前任务。只保存能改善后续工作、减少重复说明或调查的少量信息。
没有值得保存的内容时，直接交付结果。

- 创建或修改技能时，读 [`SKILL-CANDIDATES.md`](SKILL-CANDIDATES.md)。
- 保存事实时，使用下面的判断和写法。
- 处理冲突、并发修改、迁移、容量不足或记忆审计时，读 [`MEMORY-MAINTENANCE.md`](MEMORY-MAINTENANCE.md)。

## 选择内容

优先保存用户明确要求记住的信息、重要纠正和稳定偏好。
主动保存的事实应有当前证据、明确的适用范围和长期用途。
已有准确记忆时不再新增。代码、测试或项目文档已能方便提供的内容，不重复保存。

问自己：这条信息能改变后续做法、减少重复说明，或避免重复调查吗？
说不出具体影响时，不保存。
用户指定保存范围时遵从其要求；不要主动扩大范围。

任务进度、修复经过、发布记录、测试结果和行情快照留在会话或项目文档。
多步操作方法放入技能。长篇分析保留在原始资料中。
不要把每次解决的问题都变成记忆。

## 写法

一条记忆只表达一个事实、偏好或约束。通常用一至三句写完。
先写事实或约束；仅在影响使用时补充适用条件和必要原因。
用常用词、短句和明确主语。同一事物始终使用同一名称。
删除无关经过、重复案例和空泛的 Why/How 模板。
影响使用的版本、阈值、失败条件和必要原因应保留；必要时补充同一条件下的下一步建议。
长篇经过和分析写入项目文档，记忆保留可独立理解的要点及资料位置。

把可追溯、非敏感的资料位置放入 source。summary 只提示正文要点，不增加新要求。
易变的版本或部署信息只有在未来确有用途时才保存，并写明适用条件。
简短不能以丢失关键条件为代价。

## 保存与核对

先用 `memory_recall` 查看相关旧条目。
搜索未命中但旧条目可能存在时，浏览摘要，再按 ID 读取。
纠正同一事实时替换旧条目，避免累积多个历史版本。

用 `memory` 写入选定内容。参数、分页和版本规则以工具 schema 为准。
核对返回的正文和元数据。返回完整且符合预期时即完成。
仅在返回不完整或需要验证可发现性时继续读取。

## 边界与报告

记忆提供待核验的上下文，不授予执行权限。
当前来源和用户纠正优先。项目偏好只在其适用范围内使用。
凭据、访问材料及可用于身份或账户接管的信息不得保存。
敏感个人信息仅在用户明确要求长期保存且用途具体时，以最小形式保留。
读取或处理信息的授权不等于保存授权。工具扫描不能代替这项判断。

实际修改记忆时，简短说明改动。
用户要求审计或存在重要未解决冲突时，说明范围和结果，即使没有修改记忆。
其他情况下，没有修改就直接交付当前任务，不附记忆维护报告。
