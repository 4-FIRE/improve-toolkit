# 复盘与进化

目标是维护一组短小、可信、跨会话仍有价值的记忆，并发现值得复用的流程。不要把复盘做成完成日志，也不要未经授权把工作流写成技能。

## 先判断是否值得写

每条候选内容都问：

> 三周后的新会话里，如果用户不再提醒，我还需要知道这件事吗？

优先级：

1. 用户纠正、明确偏好和稳定个人信息
2. 项目约定、环境约束、API 特性等稳定事实
3. 其他难以重新发现、未来仍会影响判断的事实

没有内容通过门槛时，直接说明“没有需要长期沉淀的内容”。

## 事实与流程分开

记忆只保存“是什么”或“为什么”，不保存“怎么做”：

- 命令、代码片段、排障步骤、条件分支和完整工作流不进记忆。
- 可以从流程中提取稳定根因或项目约束作为事实。
- 流程性知识默认留在当前会话；达到下述门槛时可以主动提出技能提案。

## 技能候选

只在任务结束或复盘节点提出候选，每个任务最多一个。候选至少满足以下三项：

1. 已在本轮实际验证成功。
2. 包含非显而易见的多步流程或关键坑点。
3. 未来有较高概率重复使用。
4. 相比重新探索，沉淀能显著节省成本。

普通操作、一次性修复和通用常识不提案。

提案前先检查目标路径，并向用户一次说明：

- 技能名与完整目标路径
- 解决的问题和触发场景
- 本轮验证依据
- 计划写入的核心步骤与资源文件
- 明确询问是否按该方案创建或修改

默认目标是当前项目、当前宿主的技能目录：

- Codex：`<project>/.agents/skills/<skill-name>/`
- Claude Code：`<project>/.claude/skills/<skill-name>/`

不得把插件安装目录、缓存目录或全局技能目录作为默认目标。其他目录存在同名技能时只提示冲突，不编辑、迁移或删除。

提案前不生成完整 `SKILL.md`，用户未同意时不写文件。用户同意即授权在提案所示路径实施，无需再次确认；实施时加载 `writing-great-skills`，并用宿主原生文件工具编辑。

若目标路径已存在，把提案明确写成修改方案，列出涉及文件和改动范围；未经同意不覆盖。如果现有技能错误、过时或触发不准，也遵循同一修改提案流程。

用户拒绝后，本轮不再提出同一候选，也不把拒绝写入 memory。用户未回应时视为未授权，不追问、不建立待办队列；只有出现新的关键证据或用户主动重提时才再次建议。

## 选择记忆目标

| Target | 适用范围 | 示例 |
| --- | --- | --- |
| `user` | 换项目仍成立的用户信息或偏好 | `User prefers concise responses. Why: long summaries obscure decisions.` |
| `memory` | 换维护者仍需知道的项目事实 | `Project requires Python 3.10+.` |

## 写入前自检

- 使用陈述句，不写会被当作即时指令的祈使句。
- 一条只表达一个事实；纯事实一行，偏好可附一句 Why。
- 不保存任务进度、完成日志、临时 TODO、当前 commit、临时端口或一次性试错。
- 不复制可随时查阅的长清单；写“原则 + Why + source of truth 指针”。
- 先查看已有记忆：重复则 no-op，更准确则 replace，过时则 remove。
- 不在内容中添加 YAML frontmatter，存储格式由 memory 工具管理。

## 腾退

记忆是有限工作集，不是 append-only 日志：

- 被当前事实证伪：`memory(action='remove')`
- 同一事实有更准确版本：`memory(action='replace')`
- 多条表达同一事实：合并后删除重复项
- 容量接近上限：优先删除低价值、久未验证的项目事实，保留用户纠正和偏好

## 执行

调用 `memory` 时，如果 schema 提供 `project_dir`，传入当前工作区根目录的绝对路径。

1. 扫描用户信号、稳定项目事实、调试根因、现有记忆冲突和高价值流程候选。
2. 对候选项执行价值判断与写入前自检。
3. 使用 `memory(action=add|replace|remove)` 完成必要变更。
4. 在任务结束或复盘节点，按门槛决定是否提出一个技能提案；未获授权不写技能。
5. 用简短结果说明记忆变更；无变更也明确说明。
