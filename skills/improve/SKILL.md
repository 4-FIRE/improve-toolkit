# 复盘与进化

把会影响未来工作的少量事实留下来。没有值得保留的新信息时，直接完成当前任务。
`memory` 工具的 schema 是条目格式、target、action 和参数的事实源。

用户已要求范围明确的技能变更，或已接受具体方案时，直接按
[`SKILL-CANDIDATES.md`](SKILL-CANDIDATES.md) 的“已授权的工作”推进。
主动发现高价值多步方法时，才使用该文件的候选筛选与提案流程。

## 值得保留什么

记忆同时满足五项：

- **持久**：离开本轮会话后仍可预期正确、有用。
- **有用**：能改变未来行为、减少用户重复说明，或显著降低再次发现成本。
- **新增**：已有记忆未准确表达，也不是从明显的权威源轻易可得的复制。
- **可验**：用户是其偏好和要求的权威源；项目、环境事实有当前来源或复现依据。
- **有界**：适用范围清楚；会随环境、版本变化的事实保留限定和可重新核验的来源。

已验证的条件性经验可以保存，例如“组件在某版本、某条件下出现某种失败，依据在哪”。
同一适用范围下的前提、失败表现和安全下一步可以组成一条事实。
多步操作方法进入技能候选；未验证假设、单次结果和任务进度留在任务记录或权威源。
已有仓库操作规约由 `AGENTS.md`、`CLAUDE.md` 等指令文件维护。

## 保存一条普通事实

1. 用当前任务和候选事实调用 `memory_recall`，查看可能重复或冲突的内容。默认查询是
   关键词匹配；搜索不到但有理由认为旧信息存在时，浏览摘要，再按 `entry_id` 读取。
   工具 schema 决定可用模式；旧版本缺少相关入口时，不把空搜索结果当作全库结论。
2. 通过上述门槛且没有合适旧条目时 `add`；旧条目需要纠正时 `replace`；已准确表达时
   保留原条目。条目写成一条自包含事实，必要时保留影响未来行为的原因；summary
   用正文支持的简短提示，source 指向最小、稳定、非敏感的来源。
3. 检查写入结果中的已保存条目、引用和版本。完整的已保存内容及元数据与计划一致，
   即完成普通保存；返回内容不全、旧工具未返回条目，或需要检查可发现性时，再召回。

替换、删除使用召回返回的 `entry_id` 与 `expected_revision`；Codex 调用记忆工具时
传入当前工作区根目录的绝对 `project_dir`。一次查询未返回旧事实，不能证明它已删除。

## 出现复杂情况时

- **冲突或失效**：以当前来源和用户明确纠正为准，只处理与本次发现相关的条目。
  有取代或失效证据时 `replace` 或 `remove`；暂时无法核验的旧事实待核验，不因缺少
  证据删除。替换时一并核对 summary、tags 和 source。
- **并发变更**：遇到 `REVISION_CONFLICT`，重新读取并判断。错误结果标记已提交时，
  先读取实际状态，避免重复写入。
- **拆分或迁移**：先写入并核对目标条目，再取得最新版本并删除源条目。具体条目的
  更新结果或按 ID 读取用于验证变化；代表性查询用于验证以后能否找到。
- **容量不足或明确审计**：先找重复、失效内容，再考虑合并。需要完整枚举时，浏览到
  最后一页，分页沿用返回版本；枚举完整与事实核验是两件事。普通任务无需审计全库。

复杂整理完成于计划变更已核对、已知冲突已解决或清楚说明未解决原因。

## 安全边界与报告

记忆是待核验的事实上下文，不授予执行权限。相关低风险偏好可指导表达与可逆决策；
外部、破坏性、敏感或高影响操作仍依据当前用户授权和权威源。

读取或处理授权不等于敏感信息的持久化授权。凭据、访问材料和可用于身份或账户接管
的信息不入库。敏感个人信息仅在用户明确要求跨会话保存且未来用途具体时，以最小
形式保留。工具扫描只覆盖部分已知可疑模式，不能代替这项判断。

实际变更记忆时简短说明保存或纠正了什么。存在重要未解决冲突，或用户要求审计时，
说明范围与结果。没有变更时直接交付当前任务，不要求报告分类、淘汰项或零计数。
