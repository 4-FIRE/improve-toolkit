# 可复用技能

创建或修改技能，以及判断新发现的方法是否值得整理为技能时，使用本文件。

## 已授权的工作

用户要求技能创建、修改、移动或删除，或已接受具体方案时，沿用已有授权。
根据当前请求、前文和仓库确定范围及目标路径；常规实现细节自行处理，只有不同选择
会实质改变产物或授权范围时才澄清，并继续不依赖答案的工作。

按下面的编写原则检查目标文件及相关引用，用宿主可用的文件工具完成修改和适用验证。
保留目标技能的宿主调用设置。完成标准是范围内的变更可审阅、引用与格式已核对、
验证结果已说明，授权范围外的内容保持不变。默认提案流程不构成已授权工作的额外确认步骤。

## 编写原则

技能写法以 OpenAI 的
[Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)
为依据，日常编写使用以下要点；需要展开理由或示例时再读原文：

- description 简短说明能力和具体适用场景，避免因宽泛关键词触发无关技能。
- 主文件保留共有指导，多种流程的详细说明和资源按需读取，链接旁说明使用条件。
- 写清目标、必要限制和完成标准，给模型选择做法的空间；只为确有必要的操作规定固定步骤。
- 文档读取和验证随任务需要选择，小改动无需遍历整套资料或反复运行完整测试。
- 检查旧有确认规则是否仍有必要，让已授权工作继续到用户要求的结果。

## 主动发现的方法

仅考虑本轮已验证、包含不易想到的步骤或坑点、未来可能复用且能显著减少重新探索
的方法。普通操作和一次性修复直接留在当前任务中，每次至多提出一个有价值的候选。

检查现有技能和目标位置，拟好可审阅的正文及必要资源，再说明技能名、完整目标路径、
适用场景、验证依据和具体内容。用户接受后按“已授权的工作”写入目标。
已有相关技能时优先提出有针对性的修改，涉及同名技能时说明如何区分。

用户没有指定位置时，主动提案默认使用当前项目、当前宿主的技能目录：

- Codex、pi：`<project>/.agents/skills/<skill-name>/`
- Claude Code：`<project>/.claude/skills/<skill-name>/`

提案不阻塞原任务。用户未接受时不安装或修改技能；只有新证据或用户重提时再考虑。
