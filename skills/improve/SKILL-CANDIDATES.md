# 技能候选与授权

本文件专门处理可复用流程；事实记忆由主技能的记忆整理步骤处理。每个任务最多让一个候选进入提案。

## 已授权的工作

用户主动要求范围明确的技能创建、修改、移动或删除，或接受具体方案，即已授权。
先根据当前请求与前文确定目标路径和涉及文件；上下文已明确的范围直接沿用。
加载 `writing-for-agents`，检查现有内容，用宿主原生文件工具实施并运行适用验证。
完成标准：范围内的变更已完成，授权范围外的内容保持不变，验证结果已核对并向用户说明。

下列筛选与提案只用于主动发现的经验，不是用户已授权工作的前置步骤。

## 主动发现的候选

候选必须同时满足四项：

1. 已在本轮实际验证成功。
2. 包含非显而易见的多步流程或关键坑点。
3. 未来有较高概率重复使用。
4. 相比重新探索，沉淀能显著节省成本。

普通操作、一次性修复和通用常识归入不合格候选并关闭。完成标准：每个流程候选都已判定合格或不合格，至多一个合格候选继续。

## 具体提案

主动发现的合格候选先提出方案。检查目标路径，然后向用户一次说明：

- 技能名与完整目标路径
- 解决的问题和触发场景
- 本轮验证依据
- 计划写入的核心步骤与资源文件
- 是否按该方案创建、修改、移动或删除

提案说明可审阅的范围和核心内容，用户接受后按“已授权的工作”实施。默认目标是当前项目、当前宿主的技能目录：

- Codex：`<project>/.agents/skills/<skill-name>/`
- Claude Code：`<project>/.claude/skills/<skill-name>/`

用户明确指定时可以使用其他路径。目标已存在时，提案列出涉及文件和修改范围；其他目录存在同名技能时，在提案中报告冲突并保持目标不变。完成标准：用户收到一个路径、范围和验证依据均明确的具体方案，以及一个授权问题。

用户未接受时，结束本次主动提案，不阻塞原任务。新的关键证据或用户主动重提时再判断。
