# 技能候选与授权

本文件专门处理可复用流程；事实记忆由主技能的记忆整理步骤处理。每个任务最多让一个候选进入提案。

## Candidate

候选必须同时满足四项：

1. 已在本轮实际验证成功。
2. 包含非显而易见的多步流程或关键坑点。
3. 未来有较高概率重复使用。
4. 相比重新探索，沉淀能显著节省成本。

普通操作、一次性修复和通用常识归入不合格候选并关闭。完成标准：每个流程候选都已判定合格或不合格，至多一个合格候选继续。

## Proposal

主动发现的合格候选先进入 proposal。检查目标路径，然后向用户一次说明：

- 技能名与完整目标路径
- 解决的问题和触发场景
- 本轮验证依据
- 计划写入的核心步骤与资源文件
- 是否按该方案创建、修改、移动或删除

提案的粒度止于方案；完整 `SKILL.md` 属于 authorized 实施。默认目标是当前项目、当前宿主的技能目录：

- Codex：`<project>/.agents/skills/<skill-name>/`
- Claude Code：`<project>/.claude/skills/<skill-name>/`

用户明确指定时可以使用其他路径。目标已存在时，提案列出涉及文件和修改范围；其他目录存在同名技能时，在提案中报告冲突并保持目标不变。完成标准：用户收到一个路径、范围和验证依据均明确的具体方案，以及一个授权问题。

## Authorized

以下任一事件使技能工作进入 authorized 状态：

- 用户主动要求一项范围明确的技能创建、修改、移动或删除。
- 用户接受具体 proposal。

授权范围等于用户请求或 proposal 中列出的路径和文件。proposal 被拒绝或未获回应时进入 closed 状态；新的关键证据或用户主动重提会开启新的候选判断。完成标准：状态为 authorized 或 closed，且 authorized 状态具有明确路径和文件范围。

## Implemented

进入 authorized 状态后，完整加载 `writing-for-agents`，检查目标路径的现有内容，并用宿主原生文件工具实施。保留授权范围外的内容，并在变更后运行适用验证。完成标准：授权范围内的文件已按方案完成并通过验证，结果已向用户说明。
