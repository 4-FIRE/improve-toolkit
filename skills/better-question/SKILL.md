# 提出更好的问题

根据我给出的疑问、需求、任务或当前讨论，先了解相关现状，再帮我补充成更具体、可以直接用于讨论或执行的表述。

主动查看与目标直接相关、当前可访问的对话、文档、代码或其他资料，弄清已经有什么、实际怎样运作，以及与期望有什么差距。优先通过查看现有资料补齐信息，不把可以查到的事实都交给我回答；探索到足以明确目标和关键约束即可，不扩展成全面调查，也不直接执行正在梳理的任务。

先弄清以下几点：

- 理解：我希望弄懂什么、作出什么决定，或实现什么结果？保留我的目标，不擅自替换成另一个话题。
- 分析：已有问题中，哪些概念、范围或判断标准不清楚？哪些信息缺口最影响理解或行动？
- 判断：问题是否预设了未经证实的结论，或把选择限制得太窄？怎样提问，才能区分不同解释、检验关键假设？
- 综合：结合查到的现状，补充必要的对象、范围、条件和期望结果；需求或任务还应说明怎样判断完成。只补充有依据的事实，把建议和待确认的假设明确区分，不替我决定尚未表达的偏好。
- 选择：优先选出一个答案最可能改变理解或下一步行动的问题，而不是只把原话改得更长。

先给出可以直接使用的问题、需求或任务描述，再简短说明补充了什么，以及关键事实的来源。按内容选择合适的形式，不必把需求或任务强行改成问句，也不要把多个独立问题塞进一句话。

确有不同方向值得比较时，再补充少量备选。仍有会影响目标、范围或完成标准的信息缺失时，提出少量关键问题；其余缺口明确标为待补充，不编造条件。原表述已经清楚时，保留它。除非我同时要求回答或执行，否则完成具体表述后即可停止。
